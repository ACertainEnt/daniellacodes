## Relevant deployment / build errors (all fixed)

1. `500 FUNCTION_INVOCATION_FAILED` on every API route. Vercel transpiled each `api/*.ts` in isolation and left `../server/app` unresolved: `ERR_MODULE_NOT_FOUND: Cannot find module '/var/task/server/app'`. Fixed by bundling the whole app into one `api/index.js` with esbuild.
2. `[db:exam_variants] value "2655412724" is out of range for type integer`. SQLite accepted the unsigned FNV-1a hash; Postgres `integer` is signed 32-bit. Fixed by returning `h | 0` (identical PRNG sequence because `mulberry32` applies `seed |= 0`).
3. Boolean mismatch: seed writes `published: 1` / `approved: 1` and queries `where: { passed: 1 }`. Fixed at the SupabaseRepo boundary (0/1 → boolean on writes and filters, back on reads).
4. Local SQLite `schema.sql` lookup broke after bundling (`ENOENT .../api/schema.sql`). Fixed with a source-tree fallback. Production uses the Supabase driver, but the local path now works too.
5. Cold-start seeding re-ran ~300 row checks on every invocation. Added `settings.seed_complete` short-circuit and a 300 s function timeout.
6. Runtime logs required a Vercel SSO login, so boot errors were surfaced temporarily through a gated probe, then removed.
7. Non-fatal build warnings: Node `engines: >=22.5.0` auto-upgrade notice, npm `cache-dir` config notice, esbuild install-script allowlist notice.
